# iOS Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get On Paper launching on a physical iPhone/iPad, and answer the two unknowns that gate every downstream estimate — whether `createPDF` honours rects on iOS, and whether the PDF host should be an iframe or a native offscreen webview.

**Architecture:** Three durable changes (capability split, iOS config, CI guard) followed by three throwaway spikes. The durable changes are desktop-neutral and land on `next` normally. The spikes live on a `spike/ios-*` branch and are **never merged** — their deliverable is a written finding in `docs/ios/phase-0-findings.md`.

**Tech Stack:** Tauri 2.11.2, wry 0.55.1, tauri-cli 2.11.2, Rust 1.92, objc2 0.6 / objc2-web-kit 0.3, Xcode 26.6, Vite 8, React 19.

**Spec:** [`../specs/2026-08-09-ios-ipados-port-design.md`](../specs/2026-08-09-ios-ipados-port-design.md)

**Why this split:** `updater:default` does not exist in the iOS ACL, because `Cargo.toml:69` cfg-gates `tauri-plugin-updater` off iOS. `build.rs` resolves capability permissions against the target's schema, so this is a hard build error and it is the *first* thing that breaks. ### Task 2: iOS configuration overlay and the scene manifest

**Files:**
- Create: `resume-designer/src-tauri/tauri.ios.conf.json`
- Create: `resume-designer/src-tauri/Info.ios.plist`

**Interfaces:**
- Consumes: Task 1's green iOS check.
- Produces: an iOS config that Task 3's `tauri ios init` reads. Specifically sets `IPHONEOS_DEPLOYMENT_TARGET = 17.4` and installs the scene manifest that lets the app launch on the iOS 27 SDK.

**Why `Info.ios.plist` and not an XcodeGen template:** `tauri-utils-2.9.3` `IosConfig` documents `info_plist` as "Path to a Info.plist file to merge with the default Info.plist. Note that Tauri also looks for a `Info.plist` and `Info.ios.plist` file in the same directory as the Tauri configuration file." `src-tauri/` is tracked; `src-tauri/gen/` is gitignored and regenerated on every `tauri ios init/dev/build`. Putting the manifest in `src-tauri/Info.ios.plist` means it survives regeneration with no template to maintain.

**Why the scene manifest at all:** on the iOS 27 SDK an app with **no** `UIApplicationSceneManifest` fails to launch with `NoSceneLifecycleAdoption`. An empty `<dict/>` also crashes. Only a *static* `UISceneConfigurations` entry naming tao's delegate launches. This machine has an iOS 27.0 simulator runtime installed, so this is live, not theoretical.

- [ ] **Step 1: Create the iOS config overlay**

Create `resume-designer/src-tauri/tauri.ios.conf.json`:

```json
{
  "app": {
    "windows": [
      {
        "label": "main",
        "title": "On Paper"
      }
    ],
    "security": {
      "devCsp": "default-src 'self'; script-src 'self' 'unsafe-eval' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com data:; style-src-elem 'self' 'unsafe-inline' https://fonts.googleapis.com data:; img-src 'self' data: blob: asset: https://asset.localhost; font-src 'self' data: https://fonts.gstatic.com; connect-src 'self' ipc: https://ipc.localhost https://openrouter.ai https://api.github.com ws: http: https:; worker-src 'self' blob:;"
    }
  },
  "bundle": {
    "targets": ["app"],
    "createUpdaterArtifacts": false,
    "iOS": {
      "minimumSystemVersion": "17.4"
    }
  },
  "plugins": {
    "updater": null
  }
}
```

Notes on each override:

- `app.windows` — Tauri merges per RFC 7396 JSON Merge Patch, so an array **replaces** wholesale. This drops `width`, `minWidth`, `transparent`, `titleBarStyle: "Overlay"`, `trafficLightPosition`, and `windowEffects`, none of which mean anything on iOS. They do not error; they are read into `WindowConfig` and silently ignored, which is worse.
- `devCsp` — the base config hardcodes `ws://localhost:3000 ws://localhost:3001`. On a physical device Tauri binds `TAURI_DEV_HOST` and you connect over a LAN or IPv6 address, so the hardcoded origins CSP-block HMR. The broad `ws: http: https:` here applies to **dev only** — production `csp` is untouched.
- `plugins.updater: null` — removes the block entirely, matching `Cargo.toml:69` where the plugin is already cfg-gated off iOS.
- `minimumSystemVersion` — **17.4, not the 13.0 default.** Leaving the default ships an app that installs on iOS 13 and throws at runtime in PDF/DOCX import.
- `developmentTeam` is deliberately **not** set here. Tauri reads the `APPLE_DEVELOPMENT_TEAM` environment variable, which keeps the team ID out of git.

- [ ] **Step 2: Create the scene manifest**

Create `resume-designer/src-tauri/Info.ios.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>CFBundleDisplayName</key>
  <string>On Paper</string>

  <!-- Required on the iOS 27 SDK. An app with no UIApplicationSceneManifest
       fails to launch (NoSceneLifecycleAdoption); an empty <dict/> also
       crashes. Only a STATIC UISceneConfigurations entry naming tao's own
       scene delegate launches. See tauri-apps/tauri#15719. -->
  <key>UIApplicationSceneManifest</key>
  <dict>
    <key>UIApplicationSupportsMultipleScenes</key>
    <false/>
    <key>UISceneConfigurations</key>
    <dict>
      <key>UIWindowSceneSessionRoleApplication</key>
      <array>
        <dict>
          <key>UISceneConfigurationName</key>
          <string>Default Configuration</string>
          <key>UISceneDelegateClassName</key>
          <string>TaoSceneDelegate</string>
        </dict>
      </array>
    </dict>
  </dict>

  <!-- Keychain + HTTPS only: textbook exempt from export compliance. -->
  <key>ITSAppUsesNonExemptEncryption</key>
  <false/>
</dict>
</plist>
```

`CFBundleDisplayName` is set here because on iOS that is what the home screen shows — `productName` in `tauri.conf.json` is subject to tauri#11257 (see Task 3).

`UIApplicationSupportsMultipleScenes` is `false`: this app has exactly one window on iOS, and multi-scene support would be a Phase 3+ iPad decision, not a Phase 0 one.

- [ ] **Step 3: Run the platform probe**

Paste into the Web Inspector console:

```js
(async () => {
  const out = {};
  out.isTauriGlobal = 'isTauri' in globalThis;
  out.navigatorPlatform = navigator.platform;
  out.userAgent = navigator.userAgent;
  out.devicePixelRatio = window.devicePixelRatio;
  out.viewport = [window.innerWidth, window.innerHeight];
  out.hasPromiseWithResolvers = typeof Promise.withResolvers === 'function';
  out.hasReadableStreamAsyncIterator =
    typeof ReadableStream.prototype[Symbol.asyncIterator] === 'function';

  // safe-area insets. Zero until viewport-fit=cover is set in index.html,
  // which is Phase 1 work — a zero here is expected, not a failure.
  const probe = document.createElement('div');
  probe.style.cssText =
    'position:fixed;top:0;left:0;padding-top:env(safe-area-inset-top);' +
    'padding-bottom:env(safe-area-inset-bottom)';
  document.body.appendChild(probe);
  const cs = getComputedStyle(probe);
  out.safeAreaTop = cs.paddingTop;
  out.safeAreaBottom = cs.paddingBottom;
  probe.remove();

  // Timing distinguishes "no-op" from "shown and dismissed".
  const t0 = performance.now();
  alert('probe — tap OK if you can see this');
  out.alertElapsedMs = Math.round(performance.now() - t0);
  const t1 = performance.now();
  out.confirmReturned = confirm('probe — tap OK if you can see this');
  out.confirmElapsedMs = Math.round(performance.now() - t1);

  try {
    const { platform } = await import('@tauri-apps/plugin-os');
    out.tauriPlatform = await platform();
  } catch (e) {
    out.tauriPlatformError = String(e);
  }

  console.log(JSON.stringify(out, null, 2));
})();
```

Interpretation:
- `alertElapsedMs` under ~5 → **no-op confirmed** (the spec's prediction). Over ~500 → a real dialog appeared, and the spec's `alert()` finding is wrong.
- `tauriPlatform` should be `"ios"`. `native.js:62`'s `PLATFORM_MAP` has no `ios` key, so `:78`'s `?? raw` returns it by fallthrough — Phase 1 makes that intentional.
- `navigatorPlatform` settles `main.js:1052`'s undo/redo modifier branch.

```rust
//! THROWAWAY SPIKE — Phase 0 only. Do not merge.
//!
//! Answers: does WKWebView.createPDF honour a rect on iOS, and is the
//! resulting MediaBox in points equal to the requested CSS pixels?

use std::sync::{Arc, Mutex};

use objc2::rc::Retained;
use objc2::runtime::AnyObject;
use objc2::{msg_send, MainThreadMarker};
use objc2_foundation::{NSData, NSError, NSPoint, NSRect, NSSize, NSString};
use objc2_web_kit::WKPDFConfiguration;
use tauri::WebviewWindow;
use tokio::sync::oneshot;

fn send_result(slot: &Arc<Mutex<Option<oneshot::Sender<Result<Vec<u8>, String>>>>>, r: Result<Vec<u8>, String>) {
    if let Ok(mut guard) = slot.lock() {
        if let Some(tx) = guard.take() {
            let _ = tx.send(r);
        }
    }
}

/// Capture `rect` (CSS px, document-relative) from the main webview and write
/// it to $TMPDIR/ios-pdf-probe.pdf. Returns the path.
#[tauri::command]
pub async fn ios_pdf_probe(
    window: WebviewWindow,
    x: f64,
    y: f64,
    width: f64,
    height: f64,
) -> Result<String, String> {
    let (tx, rx) = oneshot::channel::<Result<Vec<u8>, String>>();
    let slot = Arc::new(Mutex::new(Some(tx)));
    let slot_handler = slot.clone();
    let slot_setup_err = slot;

    window
        .with_webview(move |webview| {
            let ptr = webview.inner();
            if ptr.is_null() {
                send_result(&slot_setup_err, Err("null WKWebView pointer".to_string()));
                return;
            }
            let mtm = match MainThreadMarker::new() {
                Some(m) => m,
                None => {
                    send_result(&slot_setup_err, Err("not on the main thread".to_string()));
                    return;
                }
            };

            unsafe {
                let configuration = WKPDFConfiguration::new(mtm);
                configuration.setRect(NSRect {
                    origin: NSPoint { x, y },
                    size: NSSize { width, height },
                });

                let handler = block2::RcBlock::new(move |data: *mut NSData, error: *mut NSError| {
                    let result = if !error.is_null() {
                        let e: &NSError = &*error;
                        let desc: Retained<NSString> = e.localizedDescription();
                        Err(desc.to_string())
                    } else if data.is_null() {
                        Err("createPDF returned no data".to_string())
                    } else {
                        let d: &NSData = &*data;
                        Ok(d.as_bytes_unchecked().to_vec())
                    };
                    send_result(&slot_handler, result);
                });

                // objc2-web-kit has no iOS WKWebView class, so dispatch dynamically.
                let obj = ptr as *mut AnyObject;
                let _: () = msg_send![
                    obj,
                    createPDFWithConfiguration: &*configuration,
                    completionHandler: &*handler
                ];
            }
        })
        .map_err(|e| e.to_string())?;

    let bytes = rx.await.map_err(|e| e.to_string())??;
    let path = std::env::temp_dir().join("ios-pdf-probe.pdf");
    std::fs::write(&path, &bytes).map_err(|e| e.to_string())?;
    Ok(path.to_string_lossy().to_string())
}
```

**If `msg_send!` fails to compile or crashes at runtime**, use the second proven approach instead: copy wry's own iOS class declaration. `wry-0.55.1/src/wkwebview/ios/WKWebView.rs:88` declares `#[unsafe(super(UIView, UIResponder, NSObject))] pub struct WKWebView;` and line 375 already binds `createPDFWithConfiguration:completionHandler:` — it is only `pub(crate)`, so it needs copying (~40 lines), not importing. Record which approach worked.
