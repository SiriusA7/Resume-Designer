# Phase 3.1 — iOS survival — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make On Paper survivable on iPhone and iPad — no silent data loss, no
content trapped under the keyboard or the notch, no autocorrect corrupting
résumé text, no untappable controls, and no first-run dead end.

**Architecture:** Nine independent slices over the existing codebase. The
platform-specific behaviour is isolated into small pure modules
(`src/viewportHeight.js`, an autocorrect policy in `src/spellcheck.js`) so the
logic is unit-testable without a device, while the CSS changes ride on
`env(safe-area-inset-*)` and a `--app-height` custom property fed by
`visualViewport`. No new dependencies.

**Tech Stack:** Vanilla JS service modules, React 19 + Vite for chrome, Tailwind
3 + shadcn/ui primitives, plain CSS in `styles/`, vitest + jsdom.

## Global Constraints

- **Nothing that calls `window.confirm` may ship on iOS.** It returns an
  always-truthy Promise there, so `if (confirm(...))` always takes the
  destructive branch. This is a silent data-loss path, not a cosmetic defect.
- `window.alert()` on iOS presents a panel but returns in ~1 ms and **does not
  block**. Any code sequencing on it is broken.
- **`tauri-plugin-dialog` is the measured-safe native path.** `message()`
  presents *and resolves* on iOS (measured). `ask()` presents; its resolution is
  **inferred, not measured** — so do not put a destructive decision behind it.
- The brand is **On Paper**, two words, title case, in all user-facing copy.
- **Frozen forever:** bundle id `com.resumedesigner.app`, Cargo package name
  `resume-designer`, every `resume-designer-*` / `resume-*` storage key. Never
  sweep on the bare string `resume-` — it also names the `.resume-page` /
  `.resume-sidebar` CSS classes that pagination and PDF page-splitting depend on.
- Conventional commits; subjects must start lowercase. CI lints **every** commit
  in a PR.
- **`npm run test` alone is never a sufficient gate** — the vitest suite covers
  only service modules, so a broken import or JSX error in `src/components/**`
  passes a green suite. Every task ends with `npm run test && npm run lint &&
  npx vite build`.
- The shipped app runs in **WKWebView**, not Chromium. Layout- and
  scroll-sensitive changes must be sanity-checked in `npm run tauri:dev`.
- **`vitest.config.js` declares no `resolve.alias`.** The `@/` alias exists only
  in `vite.config.js` and `jsconfig.json`, so `@/components/...` resolves in a
  build but **not** under vitest. Every import added to a `src/*.js` service
  module in this plan is therefore relative and carries its extension. Do not
  "tidy" them to the alias — the failure is invisible until someone writes the
  first test that imports that module.
- Baseline at the start of this plan: **992 tests green**, lint 0 errors.

```js
// resume-designer/test/noBlockingDialogs.test.js
import { describe, it, expect } from 'vitest';
import { readFileSync, readdirSync, statSync } from 'node:fs';
import { join } from 'node:path';

// window.alert/confirm are unusable on iOS: confirm() returns an always-truthy
// Promise (so `if (confirm(...))` always proceeds) and alert() does not block.
// The ONE permitted use is native.js's web fallback, which is unreachable on
// Tauri — isTauri is true on iOS, so showMessage returns before reaching it.
const ALLOWED = new Set(['src/native.js']);

function jsFiles(dir, acc = []) {
  for (const entry of readdirSync(dir)) {
    const full = join(dir, entry);
    if (statSync(full).isDirectory()) jsFiles(full, acc);
    else if (/\.(js|jsx)$/.test(entry)) acc.push(full);
  }
  return acc;
}

describe('no blocking browser dialogs', () => {
  it('never calls window.alert or window.confirm outside the web fallback', () => {
    const offenders = [];
    for (const file of jsFiles('src')) {
      const rel = file.replace(/\\/g, '/');
      if (ALLOWED.has(rel)) continue;
      const source = readFileSync(file, 'utf8');
      source.split('\n').forEach((line, i) => {
        if (line.trimStart().startsWith('*') || line.trimStart().startsWith('//')) return;
        // Bare calls only: `confirm(` / `alert(` not preceded by `.` or a word
        // character, so `confirmDestructive(` and `props.confirm(` are fine.
        if (/(^|[^.\w])(alert|confirm)\s*\(/.test(line)) {
          offenders.push(`${rel}:${i + 1}: ${line.trim().slice(0, 80)}`);
        }
      });
    }
    expect(offenders).toEqual([]);
  });
});
```

### Task 3: Keyboard-safe viewport height (B7)

Three levels of `100vh` + `overflow: hidden` make keyboard avoidance
structurally impossible: `main.css:189-193` (`html, body { height: 100%;
overflow: hidden }`), `:213` (`.app { height: 100vh }`), `:220`
(`.app-content { height: calc(100vh - var(--header-height)) }`), plus
`:1339` and `chat.css:320`.

On iOS, `100vh` is the *large* viewport and does not shrink when the software
keyboard appears, so a focused field can sit underneath it with nothing
scrollable. `100dvh` does not help either — WKWebView does not fold the
keyboard into the dynamic viewport. `window.visualViewport.height` **does**
shrink, so drive a `--app-height` custom property from it and fall back to
`100dvh` where the API is missing.

```js
// resume-designer/src/viewportHeight.js
/**
 * Keyboard-safe app height.
 *
 * `100vh` is the LARGE viewport on iOS: it does not shrink when the software
 * keyboard appears, and `100dvh` does not either in WKWebView. `visualViewport`
 * does. So publish its height as `--app-height` and let the CSS fall back to
 * `100dvh` wherever the API is absent (older engines, the print window).
 */

/**
 * @param {{visualViewportHeight?: number, innerHeight?: number}} input
 * @returns {number|null} px height, or null to leave the CSS fallback in place
 */
export function computeAppHeight({ visualViewportHeight }) {
  if (!Number.isFinite(visualViewportHeight) || visualViewportHeight <= 0) return null;
  // Floor rather than round: a fractional height rounded UP overflows the
  // viewport by a pixel and reintroduces the scroll it exists to prevent.
  return Math.floor(visualViewportHeight);
}

/**
 * Publish `--app-height` and keep it current. Returns a teardown function.
 * @param {HTMLElement} [target]
 * @returns {() => void}
 */
export function installViewportHeight(target = document.documentElement) {
  const vv = typeof window !== 'undefined' ? window.visualViewport : null;

  const sync = () => {
    const height = computeAppHeight({ visualViewportHeight: vv?.height });
    if (height == null) target.style.removeProperty('--app-height');
    else target.style.setProperty('--app-height', `${height}px`);
  };

  sync();
  if (!vv) return () => {};

  // `scroll` as well as `resize`: iOS scrolls the visual viewport to reveal a
  // focused field, and the height can settle a frame after the resize.
  vv.addEventListener('resize', sync);
  vv.addEventListener('scroll', sync);
  window.addEventListener('orientationchange', sync);
  return () => {
    vv.removeEventListener('resize', sync);
    vv.removeEventListener('scroll', sync);
    window.removeEventListener('orientationchange', sync);
  };
}
```

```js
// Kinds where autocorrect is welcome: free text the user is writing FOR a
// machine to read, where a substitution is harmless and a typo is not stored.
const AUTOCORRECT_KINDS = new Set(['chat']);

/**
 * Autocorrect policy — deliberately far stricter than spellcheck.
 *
 * Résumé fields round-trip through `textContent` into the store
 * (`inlineEditor.js`), so a WebKit autocorrection is persisted with no undo and
 * no signal. Worse, the live value carries raw markdown markers, so smart
 * punctuation rewrites `**bold**` into curly quotes and dashes. Spellcheck only
 * squiggles; autocorrect edits.
 *
 * @param {string} [fieldKind] @returns {boolean}
 */
export function shouldAutocorrect(fieldKind) {
  return AUTOCORRECT_KINDS.has(fieldKind);
}

// The attribute set that disables WebKit's text substitution on an editable.
// `autocorrect` and `autocapitalize` are the iOS-relevant pair; `autocomplete`
// stops the keyboard's strip offering stored form values.
export const EDITABLE_TEXT_ATTRS = {
  autocorrect: 'off',
  autocapitalize: 'off',
  autocomplete: 'off',
};
```

### Task 6: Coarse-pointer touch-target floor

Apple's HIG floor is 44×44 pt. The app's icon buttons are sized for a mouse.
Rather than resize every control on every platform, raise the floor only where
the pointer is coarse, so desktop density is untouched.

**Files:**
- Modify: `resume-designer/styles/main.css` (append a new block)

**Interfaces:**
- Consumes: nothing
- Produces: nothing

- [ ] **Step 1: Add the coarse-pointer block**

The two classes below are the app's own icon buttons: `.zoom-btn`
(`main.css:788`, a fixed `30px` square) and `.header-tools-btn`
(`main.css:567`). There is no `.icon-btn` in this codebase — shadcn buttons
carry Tailwind `size-*` utilities instead and are covered separately by the
`size-9`/`size-7` classes their components set, which are out of scope here.

Append to `resume-designer/styles/main.css`:

```css
/* ===== Touch-target floor =====
   44x44pt is Apple's HIG minimum. Scoped to `pointer: coarse` so desktop
   density is untouched — a mouse does not need the padding, and widening the
   toolbar on the Mac would push controls off a narrow window.

   `min-width`/`min-height` beat the fixed `width: 30px; height: 30px` on
   .zoom-btn (a min-* always wins over the corresponding width/height), and
   .zoom-btn is already a centred flex box, so the glyph stays 30px inside a
   44px tap target rather than scaling up. */
@media (pointer: coarse) {
  .zoom-btn,
  .header-tools-btn {
    min-width: 44px;
    min-height: 44px;
  }
}
```

### Task 9: Stop the updater error toast on iOS

`updateFlow.js:102` runs a background update check on startup. `isTauri` is
true on iOS, so it calls `check_update_on_channel` — a `#[cfg(desktop)]`
command that does not exist there — and the user sees **"Updater error: Command
`check_update_on_channel` not found"** on first launch. Screenshotted in Phase
0. Apps distributed through the App Store must not self-update, so the check
should not run on iOS at all.

- [ ] **Step 3: Add the predicate**

```js
/**
 * True on iPhone/iPad. Mirrors the platform gate in index.html.
 *
 * iPadOS 13+ reports a Macintosh user agent, so the UA alone is not enough —
 * `maxTouchPoints > 1` is the discriminator, and a real Mac reports 0. Getting
 * this wrong in the other direction blanked the iPad once already.
 *
 * @param {string} [userAgent] @param {string} [platform] @param {number} [maxTouchPoints]
 */
export function isIOSPlatform(
  userAgent = navigator.userAgent,
  platform = navigator.platform,
  maxTouchPoints = navigator.maxTouchPoints,
) {
  return /iPad|iPhone|iPod/.test(userAgent) || (platform === 'MacIntel' && maxTouchPoints > 1);
}
```
